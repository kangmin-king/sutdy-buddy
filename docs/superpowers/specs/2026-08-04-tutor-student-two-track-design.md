# Design: 학생/관리자 투트랙 구조 + 열품타식 학습 실행 추적

## Context

팀원 피드백(2026-08-03)과 실제 과외 경험을 바탕으로 제품 방향을 전환한다.

- 기존 앱은 기능이 너무 많고, 학생 입장에서 처음 들어갔을 때 뭘 해야 할지 설명이 필요했다. 플래너는 매일 쓰는 도구라 단순해야 한다.
- 컨디션 입력, AI 학습 패턴 분석/추천은 실제로는 정확한 분석이 어렵고(방학/개학 등 일정 편차가 큼) 일정 자체와는 무관하다는 판단.
- 현재 디자인은 학생보다 과외쌤/학부모가 관리하기 좋은 구조였다.
- 실제 문제: 과외 학생들이 매일 하도록 낸 숙제를 몰아서 하고, 학부모/과외쌤이 확인할 방법이 없다.

이 설계는 앱을 **학생용**과 **관리자(과외쌤·학부모)용** 투트랙으로 나누고, 학생 쪽 핵심을 "숙제/계획을 열품타처럼 시작·정지·완료로 시간을 재며 실행하고, 그 기록을 관리자가 확인한다"로 좁힌다.

## 계정 / 연결 구조

- 계정 역할 2종: `student`, `manager`(과외쌤·학부모 — UI/권한 동일, 명칭만 다를 수 있음)
- 학생 가입 시 고유 초대 코드 생성. 관리자는 그 코드를 입력해 학생과 연결.
- 한 학생에 관리자 다수(과외쌤 + 학부모 등) 동시 연결 가능 — 다대다 관계.
- 로그인 후 `state.profile.role`(또는 별도 계정 타입 필드)에 따라 완전히 다른 화면 트리를 렌더링. 기존 Supabase 프로젝트/Auth 재사용.

## 데이터 모델 변경 (신규 테이블, `sb_` 접두사 유지)

- `sb_student_manager_links`: `student_id`, `manager_id`, `linked_at` — 다대다 연결
- `sb_homework_assignments`: 관리자가 등록하는 반복 숙제 템플릿 — `student_id`, `subject_id`, `material`, `amount_per_day`(예: 페이지 수), `start_date`, `end_date`, `created_by`(관리자), `updated_at`. 서버 크론 없이 **클라이언트가 오늘 날짜를 조회하는 시점에**, 활성 템플릿 중 오늘 날짜에 해당하는 `sb_planner_items`가 아직 없으면 생성해서 채운다(지연 생성). 템플릿 수정은 이후 날짜부터만 반영하고 이미 생성된 과거 항목은 그대로 둔다.
- 기존 `sb_planner_items`에 `source` 필드 추가: `'homework' | 'self'` — 숙제(관리자 지정)인지 학생이 스스로 짠 스터디플래너 항목인지 구분. 숙제 항목은 학생이 삭제 불가, 시간만 기록.
- 실행 기록: 기존 `actualMinutes` 단일 값 대신, 시작~정지를 여러 번 반복할 수 있으므로 `sb_study_sessions`(항목당 여러 행) — 시작할 때마다 새 행을 만들고 `planner_item_id`, `started_at`, `ended_at`(정지/완료 전까지 null), `duration_seconds`를 기록한다. 캘린더의 열품타식 타임라인은 이 세션 조각들을 이어붙여 그린다.

## 학생 앱 — 4탭

### 1. 홈 (열품타 스타일 실행 화면)
- 오늘의 숙제(`source: 'homework'`) + 오늘의 스터디플래너 항목(`source: 'self'`)을 하나의 리스트로 표시, 과목별로 "시작하기" 버튼.
- 시작하기 → 실행 중 상태(타이머 카운트업), 일시정지(쉬는 시간) 가능, "학습 완료" 버튼으로 종료.
- **열품타식 "허용앱" 이탈 감지**: 실행 중(타이머 running) 허용 목록에 없는 앱이 포그라운드로 오면 강제 전환 없이 **타이머만 자동 정지**하고 해당 세션을 "이탈"로 기록(캘린더에도 이탈 표시). 허용 목록은 학생이 딴짓 멈춰 탭에서 직접 관리(기본값: 빈 목록 — 우리 앱 자체는 항상 허용).
- 화면 한쪽에 작은 포스트잇 "오늘의 할 일" — 탭하면 칠판 스타일 오버레이로 오늘 계획된 숙제+스터디플랜 전체 목록 표시(체크 상태 요약용, 실행은 홈의 시작하기로).

### 2. 캘린더
- 열품타 타임라인/블록 뷰로 과거 실행 기록을 표시(날짜 선택 시 그날의 세션 조각들을 시간대별 블록으로).
- 학생/관리자 양쪽에서 동일한 화면 재사용.

### 3. 스터디플래너
- 숙제 외 학생이 스스로 계획을 세우는 곳(과목 + 할 일 + 원하면 시간대) — 등록하면 홈 리스트에 합류.

### 4. 딴짓 멈춰
- 기존 쉬는 시간 차단 기능(수동, 인스타/유튜브/틱톡 대상)은 그대로 유지.
- 여기에 **허용앱 목록** 관리 UI 추가 — 학습 실행 중 이탈 감지에 쓰는 목록으로, 기존 차단 기능과는 별개의 설정.

## 관리자(과외쌤·학부모) 앱

- 학생 목록(과외쌤은 다수 학생 가능) → 학생 선택.
- 선택한 학생의 **숙제 등록/수정** 폼: 과목/문제집, 하루 분량, 시작일~기간. 수정 시 이후 날짜에만 반영(과거 기록은 보존).
- 선택한 학생의 **캘린더(타임라인)** 로 실행 확인 — 언제 시작해서 언제 끝냈는지.

## 보류 (이번 설계 범위 밖)

- 기존 컨디션 입력, AI 추천("오늘 하루 마무리"), 기존 방식 체크리스트/플래너 화면: 삭제 여부 미정 — 코드/화면 남겨두고 이번 개편에서는 건드리지 않는다.
- 학습 자료 목표(시험범위 진도 계산) 기능의 거취: 미정.
- 여러 관리자 중 알림/권한 세분화(예: 학부모는 보기만, 과외쌤은 숙제 등록도) — 이번 범위 밖, 우선 모든 관리자 동일 권한.

## 테스트 방향

- `sb_homework_assignments` → 날짜별 `sb_planner_items` 자동 생성 로직: 순수 함수로 분리해 유닛 테스트 (기간 밖 날짜엔 생성 안 함, 수정 시 과거 미보존 등).
- `sb_study_sessions` 조각들을 하루 타임라인 블록으로 변환하는 로직: 순수 함수, 유닛 테스트.
- 이탈 감지는 기존 `ForegroundAppAccessibilityService`의 감지 로직을 재사용하되, 대상을 고정 3종(인스타/유튜브/틱톡)이 아니라 "허용 목록에 없는 모든 앱"으로 바꿔야 해서 네이티브 쪽 변경이 필요하다 — 별도 플러그인 메서드(`isSessionActive` 상태 + 허용 목록)를 두고, 감지 시 강제 전환 대신 JS로 이벤트만 보내 타이머를 멈추게 한다.
