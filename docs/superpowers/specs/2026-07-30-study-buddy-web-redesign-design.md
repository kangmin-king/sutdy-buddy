# study-buddy 수정본 — 웹 통합 재구현 설계

## 배경

같은 PRD(스마트 청소년 자기주도 학습 지원기)를 두 갈래로 구현해왔다.

- **study-planner** (`클로드 강민/`): React Native + Expo + Supabase. 실제 인증/DB/LLM 연동까지 붙어 있고 v2(탭 네비게이션 + 히스토리 대시보드 + 설정 + 3단계 체크리스트 + 구조화 AI 추천)까지 커밋 완료된 상태.
- **study-buddy** (`클로 드강민/study-buddy/`): Stitch AI 목업 8개를 실제 동작하는 화면으로 빠르게 검증하기 위해 만든 프로토타입. Node/npm이 없다고 착오해 번들러 없이 브라우저 내 Babel 변환 + PowerShell 정적 서버로 구현했고, 데이터는 `localStorage`만, AI는 규칙 기반(if/else) 목업.

두 프로젝트를 비교한 결과, 사용자는 **study-buddy의 디자인·화면 흐름**을 더 선호하지만, **study-planner의 백엔드(Supabase 인증/DB)와 진짜 AI 연동**이 PRD의 성공 지표(3개월 MAU 100명, 7일 재방문율 30%)를 재는 데 필수적이다. 또한 Node/npm은 실제로 이 환경에 설치되어 있음을 확인했다(`node v24.18.0`, `npm 11.16.0`) — study-buddy의 번들러 없는 구조는 더 이상 필요한 제약이 아니다.

이 문서는 두 프로젝트의 장점을 교차해 새 폴더(`study-buddy-수정본/`)에 재구현하는 설계를 정의한다. 기존 두 프로젝트는 손대지 않고 그대로 남긴다(study-planner는 추가 기능 개발 중단, study-buddy는 UX 레퍼런스로 동결).

## 핵심 목표

"매일 써야 하는 앱"이라는 전제 아래, **입력 마찰을 최소화**하는 것이 이번 재구현의 최우선 원칙이다. 모든 입력 화면은 "필수 최소값 먼저, 나머지는 원할 때 펼쳐서"를 따른다.

## 아키텍처

- **스택**: Vite + React + TypeScript + Tailwind (CDN 아닌 PostCSS 빌드), 클라이언트 SPA
- **백엔드**: study-planner가 이미 쓰는 Supabase 프로젝트의 인증 + Postgres를 그대로 재사용한다. 스키마는 study-planner의 기존 5개 테이블 + `time_logs.status` / `daily_plans.ai_recommendation_detail` 확장분을 베이스로 하되, 아래 "데이터 모델" 절에서 정의하는 신규 테이블(`study_materials`)을 추가한다.
- **AI**: study-planner의 `evening-recommendation` Edge Function 패턴을 재사용해 실제 LLM 호출로 구조화된 JSON을 반환한다. study-buddy의 순수 함수 인터페이스 설계(`getHomeTip`, `getFreeTimeAndSuggestion`, `getTomorrowRecommendation`)는 그대로 유지하되, 무거운 개인화 추천(`getTomorrowRecommendation`)만 Edge Function 호출로 교체하고, 가벼운 즉시 반응형 로직(홈 화면 한 줄 조언, 빈 시간 계산)은 클라이언트 순수 함수로 남겨 네트워크 왕복 없이 즉시 표시한다.
- **네비게이션**: 라우터 없이 study-buddy 방식(로컬 state 기반 탭 전환 + 오버레이 화면) 유지. 하단 탭 5개: 홈 / 캘린더 / 플래너 / 체크 / AI 분석.
- **디자인 시스템**: study-buddy의 Stitch 기반 파스텔 톤/Plus Jakarta Sans/카드+필버튼을 그대로 이식(Tailwind 설정 토큰화).

## 화면별 설계

### 1. 플래너 — 메인/상세 2단 구조 (핵심 변경)

**메인 화면**: 오늘 할 과목을 빠르게 추가하는 리스트.
- 입력 항목은 **과목**과 **시작 시간**뿐.
- 시작 시간은 빠른 선택 칩으로 입력: `지금 바로` / `학교·학원 끝나고` / `저녁 먹고` / `자기 전`. 온보딩에서 입력한 "집중 잘 되는 시간대"에 해당하는 칩을 기본 강조 표시한다. 칩 선택 시 내부적으로 프로필의 하루 일과(등하교/학원 시간)를 참고해 구체적인 `HH:MM`으로 변환해 저장한다(예: "학교·학원 끝나고" → 캘린더에 등록된 마지막 학교/학원 일정의 종료 시각 + 10분). 캘린더에 참고할 일정이 없으면 상수 기본값(지금 바로=현재 시각, 학교·학원 끝나고=17:00, 저녁 먹고=19:30, 자기 전=22:00)을 쓴다.
- 추가된 항목은 카드 형태로 표시: 과목명 + 시작 시간 + `›` (탭하면 상세 페이지).
- 상세 정보가 하나도 채워지지 않은 항목이어도 저장/실행 가능해야 한다 — 상세는 항상 선택 사항.

**상세 페이지** (과목 카드를 탭하면 진입): 아래 항목을 포함하며, 전부 비워도 저장 가능하다.
- 학습 유형 칩(개념 학습 / 문제 풀이 / 암기 / 복습)
- 교재/자료명, 단원, 페이지 (각각 텍스트 입력)
- 종료 시간 / 소요 시간 (칩 형태, 시작 시간 기준 자동 계산되되 수정 가능)
- 시간 충돌 경고: 같은 날 다른 항목과 시간대가 겹치면 배너로 알리고 "자동 조정하기"로 다음 빈 시간대로 옮길 수 있다(빈 시간 계산은 아래 `computeFreeGaps` 로직 재사용)
- 난이도 칩(쉬움/보통/어려움)
- 휴식 패턴 선택(드롭다운): "25분 공부 + 5분 휴식(뽀모도로)" 등 프리셋 3~4개, 기본값 없음(선택 안 해도 무방)
- 우선순위: "AI 추천 순서" 표시 + 수동으로 순서 변경 가능
- 필수 과제 토글

### 2. 컨디션 입력 — 이모지 우선, 슬라이더는 선택

- 기본 화면: 이모지 5개(최상/좋음/보통/피곤/힘듦) 중 하나를 탭하면 바로 완료 가능.
- "더 자세히" 링크를 펼치면 수면 시간, 집중도 슬라이더가 나온다(피로도는 이모지 선택값에서 역산하므로 슬라이더 없음: 최상=1, 좋음=2, 보통=3, 피곤=4, 힘듦=5).
- 슬라이더를 펼치지 않고 저장해도 되며, 이 경우 AI 추천 정확도가 다소 낮아질 수 있음을 안내 문구로만 표시한다(기능 차단 없음).

### 3. 학습 기록 — 별점 + 태그 기본 노출, 서술은 선택

- 실행 체크에서 "완료"로 표시한 항목마다 진입하는 화면.
- 기본 노출: 별점(1~5) + 막힌 부분 태그(개념이해 안됨/시간부족/집중안됨/계산실수, 다중 선택) — 둘 다 한 화면에 바로 보인다(펼치기 불필요).
- "자세히 적기"를 펼치면: 막힌 부분 서술 텍스트(교재명·페이지·문제번호까지 구체적으로 적을 수 있는 placeholder 안내 포함) + 오늘의 한 줄 메모(별도 입력창).
- 별점만 탭하고 저장해도 무방.

### 4. 학습 자료 목표 (신규 기능) — 자료 단위 페이스 계산

투데잇 앱의 "총 범위 입력 → 오늘 할 분량 자동 계산" 패턴을 자료(material) 단위로 구현한다. 시험 날짜 하나에 종속시키지 않고, 자료마다 독립적인 목표일을 가진다(예: "쎈 수학"은 중간고사 전에 끝내고 싶지만 "개념원리"는 그보다 늦게까지 여유 있게).

**데이터 모델** (`study_materials` 테이블, 신규):
- `subject`: 과목
- `material_name`: 자료명 (예: "쎈 수학(상)", "개념원리")
- `total_scope`: 전체 분량(페이지 수 정수)
- `current_progress`: 지금까지 진행한 분량
- `target_passes`: 목표 회독 수 (정수, 기본 1)
- `target_date`: 이 자료를 끝내려는 날짜 (시험일과 무관하게 사용자가 직접 입력)
- `session_interval_days`: 며칠에 한 번 공부할지 (정수)

**페이스 계산** (순수 함수, `computeMaterialPace`):
```
남은일수 = target_date - 오늘
남은세션수 = floor(남은일수 / session_interval_days), 최소 1
남은분량 = total_scope × target_passes - current_progress, 최소 0
세션당분량 = ceil(남은분량 / 남은세션수)
```
목표일이 지났거나 남은세션수가 0 이하가 되면 "기한이 지났어요 — 목표일을 조정해보세요" 안내로 대체하고 계산을 생략한다.

**노출 위치**:
- 학습 자료 목표 화면(신규): 플래너 탭 상단에 "학습 자료 목표" 진입 버튼을 추가해 접근한다. 화면 구성은 자료 목록(진행률 바 포함) + 자료 추가 폼.
- 홈 화면에 "오늘의 시험 대비 목표" 카드: 오늘이 그 자료의 학습일(마지막 학습일 + `session_interval_days` 이상 경과)인 자료가 있으면 "자료명 O~O페이지" 형태로 표시. "플랜에 반영하기" 버튼을 누르면 오늘 플래너에 해당 범위가 새 항목으로 자동 추가된다(과목은 자료의 subject, 상세 페이지의 교재/페이지 필드에 세션당 분량 범위가 채워짐).

**범위에서 제외**: 회당 학습 시간(분) 입력은 넣지 않는다 — 페이스는 오직 "세션당 분량"으로만 표현하고 시간 환산은 하지 않는다.

### 5. 기존 그대로 유지하는 화면

홈, 캘린더, 실행 체크 화면은 이번 논의에서 구조 변경 요청이 없었으므로 study-buddy의 기존 구현을 그대로 이식한다(디자인 토큰만 통일).

## 마이그레이션 전략

1. study-buddy의 `.jsx` 파일들(로직/디자인은 검증됨)을 `study-buddy-수정본/src/`로 옮기며 각 파일에 `import`/`export`를 추가해 정식 ES 모듈로 전환한다. 컴포넌트 내부 로직은 그대로 두고, 이번 설계에서 변경하기로 한 화면(플래너/컨디션입력/학습기록)만 새로 작성한다.
2. `storage.jsx`(localStorage 래퍼)를 Supabase 클라이언트 호출로 교체한다. 상태 관리 패턴(Context + `useReducer` 하나)은 유지하되, 각 액션이 로컬 상태 갱신 후 Supabase에 비동기로 반영하는 형태로 바꾼다.
3. study-planner의 Supabase 스키마(5개 테이블 + 확장 컬럼)를 그대로 가져오고, 이번 설계에서 정의한 `study_materials` 테이블을 추가하는 마이그레이션을 작성한다.
4. `ai.jsx`의 `getTomorrowRecommendation`을 study-planner의 `evening-recommendation` Edge Function 호출로 교체한다. `getHomeTip`, `getFreeTimeAndSuggestion`, `computeFreeGaps`는 순수 함수 그대로 유지한다.
5. study-planner의 인증 화면(이메일/비밀번호 로그인) 로직을 study-buddy의 온보딩 앞단에 붙인다 — 로그인 → (프로필 없으면) 온보딩 → 메인 탭 흐름.

## 범위 외 (Out of scope)

- study-planner(RN/Expo) 앱에 대한 추가 기능 개발 — 동결.
- 실제 영상 생성, 보호자/교사 대시보드, 스크린타임 연동 등 PRD Phase 5 항목.
- 학습 자료 목표의 "회당 학습 시간" 입력 및 그에 따른 분당 페이스 환산 — 사용자 요청으로 제외.
