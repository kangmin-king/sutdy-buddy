**(1) 상단바에서 흰 사각형이 되지 않습니다.**

## 1. 제품이 무엇인가

한국 **과외 학습관리 앱**. 한 명의 과외 선생님(또는 학부모)이 학생 몇 명을 관리한다.

- **학생**: 오늘 할 숙제를 보고, 타이머를 켜고 공부하고, 완료를 체크한다.
- **매니저(선생님/학부모)**: 숙제를 내고, 학생이 했는지 보고, 시험 범위를 날짜별로 쪼개 배정한다.

규모는 작다. **실사용 학생 2명, 매니저 2명.** 스토어에 없고 APK를 직접 배포한다.
이 규모가 중요하다 — A/B 테스트나 데이터 기반 판단이 성립하지 않는다. 판단은 근거와 원칙으로 한다.

### 화면 구성

두 개의 셸이 있고 역할에 따라 갈린다.

```
학생   [ 캘린더 ] [ 오늘 ] [ 나 ]
매니저 [ 캘린더 ] [ 오늘 ] [ 학습설계 ]
```

- **학생 · 오늘** — 오늘 할 일 통합 목록(선생님이 낸 숙제 + 학생이 직접 넣은 계획을 한 목록에
  합치고 배지로만 구분), 타이머 시작/정지, 완료 체크
- **학생 · 캘린더** — 월 그리드, 날짜별 상세, 시험 일정
- **학생 · 나** — 프로필, 초대코드, 연결된 선생님, 주간 이행률, 테마 전환, 로그아웃
- **매니저 · 오늘** — 학생을 안 골랐으면 **학생 명단**이 이 자리에 온다. 고르면 그 학생의
  오늘 요약(완료 수·학습 시간·허용앱) + 오늘 항목 통합 목록 + 접힌 타임라인
- **매니저 · 캘린더** — 학생의 월 그리드, 숙제 제안, 시간표, 요일 설정, 미시작 알림 설정
- **매니저 · 학습설계** — 시험 등록, 과목별 목표, 교재 범위를 날짜에 분배

앱 셸은 `max-width: 480px` 중앙 정렬. 모바일 웹뷰(Capacitor Android) + 브라우저 양쪽에서 같은
코드가 돈다. 아이폰은 앱이 없어서 웹앱으로 쓴다.

## 2. 색

**모든 색은 `src/index.css`의 CSS 변수로만 정의한다.** `tailwind.config.ts`는 이름만 이어 붙인다.

```ts
const token = (name: string) => `rgb(var(--${name}) / <alpha-value>)`;
```

값을 `R G B` 채널만 적는 이유는 `bg-primary/10` 같은 투명도 표기를 그대로 쓰기 위해서다.
**하드코딩된 hex를 화면 코드에 쓰지 않는다.** 다크 모드가 `.dark` 클래스 하나로 갈리기 때문에,
한 곳이라도 hex면 그 부분만 테마를 안 따라간다.

### 다크 — "블루 글래스 B안" (저채도 인디고 네이비)

사용자가 인스타그램 릴스의 맥 데스크톱 화면(청보라 모노톤, 간유리 위젯)을 레퍼런스로 주고,
채도 시안 A/B 중 **B(저채도)** 를 골랐다. "눈이 아프지 않게"가 선택 기준이었다.

| 토큰 | RGB |
|---|---|
| `surface` | 27 24 50 |
| `surface-container-lowest` | 50 46 89 |
| `surface-container-low` | 44 41 80 |
| `surface-container` | 40 36 71 |
| `surface-container-high` | 36 32 64 |
| `surface-container-highest` | 32 29 57 |
| `on-surface` | 233 232 245 |
| `on-surface-variant` | 169 166 196 |
| `outline` | 124 120 155 |
| `outline-variant` | 58 54 96 |
| `primary` | 162 155 242 |
| `on-primary` | 22 20 43 |
| `secondary` | 111 217 174 (민트) |
| `tertiary-container` | 69 58 107 |
| `error` | 255 155 155 (밝은 코랄) |
| `warning` | 255 211 122 |
| `scrim` | 0 0 0 |

**⚠ 지키기로 한 제약 (바꾸려면 근거가 필요하다)**

1. **`surface-container-*` 사다리의 방향을 뒤집지 않는다.** 라이트에서 `lowest`가 흰 카드(가장 떠
   있는 면)로 쓰이고 있어서, 다크에서도 `lowest`를 가장 밝게 두고 내려간다. 이 규칙 덕분에 기존
   `className`을 한 줄도 안 고치고 카드/시트/내비게이션이 전부 제대로 떠 보인다.

2. **다크 `primary`는 `#A29BF2`(162 155 242)가 상한이다.** 처음엔 `#8B85E8`였는데 카드 위 글씨로
   3.96:1이라 기준(4.5)에 미달했다 — "교재 등록", "수정", "+ 시험 추가" 같은 링크가 전부 여기
   해당한다. 올려서 카드 위 5.09:1 / 페이지 위 6.95:1이 됐다. **더 밝히면 B안이 피하려던 눈부심이
   돌아온다.**

3. **다크에서 홈 히어로 카드는 `primary` 면을 쓰지 않는다.** 떠 있는 어두운 면
   (`dark:bg-surface-container-lowest`)으로 바꾼다. 라이트에서는 파란 면에 흰 글씨다.
   위계는 유지된다 — 요약 카드가 배경 대비 1.37:1, 일반 카드가 1.11:1.

### 대비 기준

- 본문·작은 글씨: **4.5:1 이상**
- 비-텍스트 요소(표식·스와치·아이콘): **3:1 이상**
- 흐리게 둘 의도인 요소(다른 달 날짜 등)는 3:1을 강제하지 않되 **2:1 부근**은 유지한다.
  다크에서 1.1:1까지 내려가 달력 첫 줄이 통째로 비어 보이는 사고가 있었다.

이 앱에서 대비는 눈대중으로 판단하지 않는다. **상대휘도 + 알파 합성으로 실측한다.**

```css
word-break: keep-all;      /* 낱말이 줄 끝에서 갈리는 것을 막는다 */
overflow-wrap: break-word; /* 단, URL·영문 패키지명처럼 띄어쓰기 없는 긴 문자열은 강제로 끊는다 */
text-wrap: pretty;         /* 마지막 줄에 한 낱말만 떨어지는 것을 줄인다 */
h1,h2,h3 { text-wrap: balance; }
```

**크기 체계** — Tailwind 기본 스케일을 쓰되 실제로 쓰이는 건 좁다.

| 용도 | 클래스 | 비고 |
|---|---|---|
| 화면 제목 | `text-xl font-bold` | |
| 히어로 숫자 | `text-xl font-extrabold tracking-tight` | |
| 섹션 제목 | `text-base font-bold` | `SectionTitle` |
| 본문 | `text-sm` | |
| 보조 | `text-xs text-on-surface-variant` | |
| 라벨·범례 | `text-[11px] font-medium` | |
| 초소형 라벨 | `text-[10px] font-semibold tracking-[0.1em]` | 히어로 카드 안 |
| 숫자 | `font-mono tabular-nums` | 시간·분 표시 |

아이콘은 **Material Symbols Outlined**, 기본 22px (`font-variation-settings: FILL 0, wght 400`).
`filled` 클래스로 `FILL 1, wght 500`.

## 4. 형태 · 간격

**모서리** — `borderRadius`를 재정의했다.

| 이름 | 값 | 쓰임 |
|---|---|---|
| `sm` | 0.25rem | |
| DEFAULT | 0.5rem | |
| `md` | 0.75rem | |
| `lg` | 1rem | |
| `xl` | 1.5rem | |
| `full` | 9999px | 버튼·칩·점 |

실제로는 **카드 `rounded-2xl`, 시트 `rounded-t-2xl`, 버튼·칩 `rounded-full`** 이 대부분이다.

**그림자** — 두 개뿐이고 둘 다 파란기가 도는 소프트 섀도다.

```
soft: 0 4px 20px -4px rgba(54,96,149,0.12)
card: 0 2px 12px -2px rgba(54,96,149,0.10)
```

**터치 타깃** — 누를 수 있는 것은 **최소 44px**. 아이콘 버튼은 `h-11 w-11`.
작아 보이게 하고 싶으면 아이콘을 줄이고 패딩으로 44px을 채운다(컨테이너가 아니라 버튼에 패딩).

**안전 영역** — 하단 고정 요소는 반드시
`pb-[calc(0.5rem+env(safe-area-inset-bottom))]`, 스크롤 컨테이너는
`pb-[calc(7rem+env(safe-area-inset-bottom))]`.

`screens/bootstrapModel.ts`로 빼서 테스트로 고정했다.

## 6. 달력 표식 규칙 (가장 조밀한 부분)

날짜 한 칸이 **일곱 가지 상태**를 동시에 표현한다. 채널이 전부 차 있어서 새 상태를 추가하려면
기존 채널을 침범하지 않는 곳을 찾아야 한다.

| 상태 | 표현 | 채널 |
|---|---|---|
| 과외 날(수업일) | 원 **위** 16×3px 가로 막대, `bg-on-surface-variant` | 상단 공간 |
| 선택된 날 | `bg-primary` 채운 원 + `on-primary` 글씨 | 면 색 |
| 오늘 | `border border-primary` + primary 글씨 | 1px 테두리 |
| 공휴일·일요일 | `text-error` 글씨 | 글자 색 |
| 시험 | 날짜 **아래** 8px **각진 네모**, `bg-error` | 아래 마커(모양) |
| 숙제/계획 있음 | 날짜 **아래** 6px **둥근 점**, `bg-secondary` | 아래 마커(모양) |
| 지난 날 이행률 | 날짜를 감싸는 원형 링 (저조=`error` / 보통=`warning` / 완료=`primary`) | 바깥 링 |

**원칙: 색만으로 구분하지 않는다.** 시험과 숙제는 색이 아니라 **크기·모양**이 다르다
(크고 각진 네모 vs 작고 둥근 점). 예전엔 시험이 날짜를 감싸는 `ring-2 ring-error`였는데,
이행률도 링이라 다크에서 `error`가 밝은 코랄로 바뀌면서 둘이 같아 보였다. 색을 더 쥐어짜는 대신
**채널을 바꿨다** — 색약 사용자에게도 이 편이 낫다.

**과외 날이 왜 막대인가**: 원래 `bg-tertiary-container/40`으로 원을 옅게 채웠는데 배경 대비가
라이트 1.46:1 / 다크 1.20:1이라 사실상 투명했다. 면을 진하게 하면 "선택된 날"과 무게가 비슷해져
섞인다. 그래서 아직 아무도 안 쓰는 **원 위쪽 공간**으로 옮겼다(라이트 8.48:1 / 다크 5.80:1).
막대 색을 `on-surface`가 아니라 `on-surface-variant`로 한 것은 의도다 — 과외 날은 그 날의
성질이지 날짜 자체보다 중요하지 않다.

**범례는 실물과 똑같은 모양을 쓴다.** 견본과 실제가 다르면 범례가 제 일을 못 한다.
학생 캘린더와 매니저 캘린더의 범례 규칙은 항상 일치시킨다 — 같은 달력을 보는 두 사람이
서로 다른 규칙을 배우면 안 된다.

## 7. 다크 모드

- `darkMode: 'class'`. `<html>`에 `.dark`를 붙인다.
- 사용자 선택은 `localStorage['sb-theme']`에 저장하고, `index.html`의 **인라인 스크립트가 첫 페인트
  전에** 읽어서 클래스를 붙인다(깜빡임 방지). `theme-color` 메타도 같이 바꾼다(`#1b1832`).
- 전환 UI는 **학생 "나" 탭의 세그먼트 컨트롤**과 **상단바 톱니 → 설정 시트**의 라디오그룹 두 곳.
- **라이트가 기본이다.** 다크는 옵트인이다.

다크 전용 오버라이드가 필요하면 `dark:` 유틸리티를 쓰되, **토큰 자체를 고쳐서 해결되는 경우가
대부분이다.** `dark:` 가 늘어나면 그건 토큰 설계가 잘못됐다는 신호다.
현재 `dark:` 규칙은 13개뿐이고, 그 정도가 적정선이라고 본다.

## 8. 이미 내려진 정보구조 결정 (되돌리려면 근거가 필요하다)

- **학생 탭 순서를 캘린더 / 홈 / 나로 두었다.** 사용자가 직접 지정했다.
- **"플래너" 탭을 없앴다.** 오늘 할 일을 홈·플래너·캘린더가 서로 다른 부분집합으로 보여줘서
  (플래너는 `source === 'self'`만) 학생이 오늘 할 일을 보려면 세 곳을 다 봐야 했다.
  탭 하나가 질문 하나만 담당한다 — 홈은 "오늘 뭐 하지", 캘린더는 "언제 뭐 있지", 나는 "내 정보".
- **매니저의 학생 명단을 별도 셸에서 "오늘" 탭의 기본 상태로 바꿨다.** 예전에는 학생을 고르기
  전엔 하단 탭이 아예 없어서 명단이 홈보다 윗 단계인지 별도 페이지인지 알 수 없었다.
- **매니저 "오늘"에서 행동할 것을 관찰할 것보다 위에 둔다.** 요약 → 오늘 할 일 → 제안 →
  (접힌) 타임라인 순. 예전엔 타임라인이 맨 위였다.
- **숙제와 자기계획을 한 목록에 합치고 배지로 구분한다.** 학생 쪽과 매니저 쪽 모두.
  수정·삭제는 숙제에만 준다(학생 계획을 관리자가 대신 고치지 않는다).
- **회원 탈퇴는 설정이 아니라 계정 정보 시트 맨 아래에 둔다.** 사용자가 직접 지정했다.
- **역할을 교사/학부모로 가르지 않는다.** 코드에 둘을 구분할 데이터가 없고 필요가 다르다는
  근거도 없다.

## 9. 알려진 문제 · 미결

### 2026-09-11 최종 디자인 리뷰에서 정리된 것 (v1.2.7)

- **알림 벨을 없앴다.** `onBell`을 넘기는 화면이 0곳이라 벨은 이제 어디에도 안 뜬다
  (prop은 남겨 뒀다 — 나중에 넘기면 다시 나타난다). **인앱 알림함은 만들지 않기로 했다**:
  푸시가 이미 가고 있어서 같은 사실을 두 곳에서 관리하게 될 뿐이고, 알림함이 담을 고유한
  내용이 없다.
- **온보딩 그라데이션을 없앴다.** 이제 앱 전체에 `bg-gradient`가 0곳이다. 다른 카드와 같은
  표면(`surface-container-lowest` + `shadow-card`)을 쓴다. 첫인상 화면이라는 이유로 다른 시각
  언어를 쓰면, 정작 매일 보는 실제 화면이 덜 만들어진 것처럼 느껴진다.
- **자기계획 완료도 매니저에게 알린다.** 추가할 때만 알리고 완료는 안 알리던 것을 맞췄다.
  숙제와 자기계획을 한 목록에 배지로만 구분해 놓았으니 알림 정책이 갈리면 그 통합이 거짓말이
  된다. 이 앱의 전제가 "했는지를 기록으로 증명한다"라 추가보다 완료가 더 중요한 사건이다.
- **초기 로드 실패 화면을 추가했다**(§5 참고). 예전에는 프로필 조회가 실패하면 기존 사용자에게
  온보딩이 떴다.

### 상단바 마스코트 — 지금은 그대로 둔다 (2026-09-11 결정)

마스코트(따뜻한 손그림 카와이 토끼: 흰색·분홍·주황·초록)와 앱 테마(찬 계열 파랑·인디고·보라)의
색 계열이 안 맞고, 상단바에서 Material Symbols의 얇은 기하선과 8px 거리에 붙어 선 두께도 안 맞는다.
PNG에 투명도가 없다(색타입 2 = RGB).

리뷰는 상단바 마스코트를 `S` 글자 배지로 바꾸라고 했지만 **그대로 두기로 했다.**

- 리뷰의 근거였던 "다크에서 흰 사각형이 된다"는 **상단바에는 해당하지 않는다** —
  `rounded-full overflow-hidden` + `object-cover`라 원으로 잘려 아바타처럼 읽힌다.
  흰 사각형이 되는 것은 랜딩 CTA였고 그건 둥근 흰 상자로 감싸 해결했다.
- 어차피 **출시 후 투명 배경으로 재제작**하기로 했으므로, 지금 글자로 바꿨다가 되돌리는 것은 왕복이다.
- 파일럿 4명 규모에서 흰 원 아바타가 고장으로 읽히지는 않는다.

재제작 때 함께 정할 것: 투명 배경(PNG/WebP 또는 SVG), 앱 토큰에 맞는 저채도 포인트,
사용처를 온보딩·랜딩·일부 빈 상태로 제한할지, 상단바에 계속 둘지.

### 남은 미결

- **매니저 정보구조 재편(§8의 셋째 항목)이 아직 실사용 검증 전이다.** 며칠 써보고 되돌릴지
  판단하기로 했다.
- `TopAppBar`의 마스코트를 감싼 `bg-primary`는 이미지가 덮어서 보이지 않는다(죽은 스타일).
  재제작 때 원 테두리로 살릴지 함께 정한다.

## 10. 이 문서를 쓰는 방법

디자인 제안을 받을 때 **다음을 지켜달라고 요구한다.**

1. **색은 토큰 이름으로 말한다.** hex를 새로 만들지 않는다. 새 색이 꼭 필요하면 토큰을 추가하고
   라이트·다크 두 값을 다 준다.
2. **대비비를 계산해서 제시한다.** 본문 4.5:1, 비-텍스트 3:1. 라이트·다크 양쪽 다.
3. **기존 채널을 침범하지 않는다.** 특히 달력(6번)과 다크 제약(2번)은 이미 사고를 겪고 정해진
   것이라 근거 없이 뒤집으면 같은 사고가 반복된다.
4. **구현 코드를 Tailwind 클래스까지 구체적으로 준다.** 말로만 된 제안은 적용할 수 없다.
5. **모바일 480px 폭**을 전제한다. 세로 공간이 비싸다 — 여백을 늘리는 제안은 무엇을 줄일지도
   같이 말해야 한다.
